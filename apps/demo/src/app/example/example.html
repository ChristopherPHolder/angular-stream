The code

Three steps. The first two are per part; the third is once per app.

  1. 1 · Put the slow part in a @defer block

    The block is what the server can send later. Everything outside it is the shell, sent at once. Give the block a hydrate when trigger that turns true when its data is there.

    The @else branch goes out with the shell, so it is what paints first.

  2. 2 · Load its data with HttpClient

    The server makes the request and streams the block when the response is in. The browser asks for the same data, but its request is held back and answered from the stream. Nothing is fetched twice.

  3. 3 · Switch streaming on

    Two additions to the app's providers, and a Cloudflare Worker entry that renders with the streaming renderer.

Three rules

  • What depends on data goes inside a block

    The shell is sent once. If something outside a block changes afterwards, the browser renders the change, and the server HTML never has it.

  • A block sits directly inside an element

    Not at the root of an @if, in an ng-container or in projected content. The server warns about such a block and leaves it to the browser.

  • Tie hydration to the data

    With hydrate when, a block hydrates as soon as its own chunk lands. hydrate on idle, immediate, timer and viewport say nothing about data, so they wait for the end of the response.
