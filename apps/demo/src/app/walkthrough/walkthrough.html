1 · The shell

Everything outside the @defer blocks below is the shell: this text, every box's frame and heading, and the placeholders inside the blocks. The server rendered it once the route was in place, without waiting for the data, and sent it in the first flush, with an inline runtime and the app's script at the end. The response stays open, and Angular starts and hydrates the shell while the rest is still on its way.

5 · Outside any block: never in the server HTML

The quotes below show data A, just like block A, but they are not inside a @defer block. They belong to the shell, which went out before data A arrived and is never sent again. So the server HTML has empty quotes, and the text appears only because Angular renders it in the browser once data A arrives. The response inspector shows the empty quotes in the shell. 6 · Requests the browser sent: {{ backend.browserRequests() }}

The page asks for all four pieces of data in the browser too. A request the server is already making is held back until its response arrives on the stream, then answered from transfer state, so the browser never fetches it. If this number goes above 0, the browser fetched something itself. That happens when the stream breaks off before all the data has arrived: the client then releases its held requests and lets them go to the network.
